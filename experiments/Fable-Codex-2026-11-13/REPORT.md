# 4量子ビットの全64接続グラフを有限ショットで識別する

2026年11月13日。開鎖とリングの比較を、4サイト上のラベル付き単純グラフ全64通りの識別に広げた。読み出し誤りが各ビットで独立に5%のとき、測定設定と回数を事前に固定するモデルで、全6辺を各グラフについて95%以上の確率で当てるための最適ショット数は **53〜99** に入る。

## 測定モデル

グラフを $G$ として、$H_G=\tfrac12\sum_i X_i+\tfrac7{20}\sum_{ij\in G}Z_iZ_j$ のもとで、毎回 $\lvert0000\rangle$ から時間発展させる。1ショットでは $0\le t\le3.688$ の時刻を選び、全4サイトを共通の X・Y・Z 基底のいずれかで測る。各ビットの読み出しは既知の確率 $p$ で独立に反転する。保証の対象は独立ショットによる事前固定の測定であり、下限もこの測定クラスに対して適用する。

## 読み出し誤り5%での上下限

| 証明書の段階 | 下限 | 上限 |
| --- | ---: | ---: |
| [有限ショット結果の初回監査](Codex/four_qubit_audit.zip) | 29 | 173 |
| [整数スコアによる追加監査](Codex/four_qubit_proof_reaudit.zip) | 29 | 103 |
| [100〜102ショットの探索と複数仮説の下限](Codex/four_qubit_p5_bounds.zip) | 50 | 100 |
| [99ショット設計と52ショットの不可能性](Codex/four_qubit_p5_99_audit.zip) | **53** | **99** |

**上限99。** Z 基底で $t=2.122$ に88回、$t=3.531$ に11回を配分する。各候補グラフの固定加点と各観測の整数スコアを合計し、一意に最大となったグラフを出力する。グラフIDのビット0〜5は辺 `01, 02, 03, 12, 13, 23` に対応する。

誤答の証明では同点も失敗に数える。有理数の Taylor 展開と剰余で観測確率を囲い、整数畳み込みで競合ごとの失敗確率を上から押さえる。競合を頂点とする森を選び、その辺に対応する同時失敗確率の下界を単一事象の上界の和から引く。サイト置換に関するスコア表と固定加点の同変性を確かめ、11代表グラフの結果を全64グラフに適用する。証明書の最悪誤答率上界は $14071113279104/281474976710656$ で、切り上げ表示で **4.999064%以下**。98・97ショットは探索済みで、全64グラフの保証は未確定。

**下限53。** 複数のグラフ対が共有する混同行列の制約で、測定設定ごとの配分を絞る。確率の時間変化も包絡し、連続時刻全体を含める。52ショットでは、辺 `23` だけが欠けたグラフを真とした場合に、6つの競合グラフを出力する確率の和が少なくとも **5.2736919284%** 必要となる。誤出力は互いに排反で、その和が許容の5%を超える。

## 元の数値実験と監査

- [全64グラフの識別可能性](Fable/verify_64_graphs.py)では、雑音のない $\lvert0000\rangle$ の時系列について、1体 XYZ 期待値で54類、2体連結相関で64類を得た。ここで使うハミルトニアンの係数は有限ショット側の2倍で、時刻 $t$ の発展は有限ショット側の $2t$ に対応する。
- [有限ショット探索コード](Fable/finite_shot_topology.py)と[元の出力](Fable/finite_shot_results.txt)を収録した。探索で得た候補のモンテカルロ結果は、[全グラフの試行数・成功数](Codex/graph_success_counts.csv)および[104ショットの別シード検証](Codex/p5_104_success_counts.csv)にある。上の表は、整数スコアなどを使った数学的証明書の上下限を示す。
- 読み出し誤り0%と2%について、初回監査の上下限はそれぞれ17〜97ショットと22〜130ショット。開鎖の既知の位置 `03` に弱い結合があるかを調べる二仮説の結果は、[追加監査ZIP](Codex/four_qubit_proof_reaudit.zip)の `re_audit_notes.txt` と証明書に収録した。

## 99ショット設計と下限の再計算

[99ショットの監査ZIP](Codex/four_qubit_p5_99_audit.zip)を作業用フォルダに展開し、そのフォルダで実行する。上限の再計算は Python と NumPy を使う。証明書作成時の環境は Python 3.12.14 と NumPy 2.3.5。保存済みの整数格子を使うため、乱数による再探索は不要。

```sh
python -B certify_p5_integer_design.py --candidate u99_screen_candidate_0.json --output union.replay.json
python -B certify_hunter_tilted.py --candidate u99_screen_candidate_0.json --union union.replay.json --forest u99_tilted_final_mixed.json --output upper.replay.json --replay
python -B verify_roc_row_lower_p5.py joint_confusion_refined_m1_witness.json roc_p5_row_cases.json lower.replay.json
```

上限は `upper.replay.json` の `worst_numerator` について `20 × worst_numerator ≤ 2^48` を満たせば合格となる。下限の検証器は52ショットの必要誤答率の下界と、52ショットを除外できるかを出力する。証明の詳細、補助検証のコマンド、同梱ファイルのハッシュは ZIP 内の `p5_99_notes.txt`、`tilted_hunter_proof.txt`、`sha256.txt` を参照。
